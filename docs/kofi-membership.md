# Forest Guardian payment access

Set the Forest Guardian tier to **USD $5 per month** in Ko-fi. In the backend environment, set `KOFI_VERIFICATION_TOKEN` to the private verification token shown on Ko-fi's [Webhooks page](https://ko-fi.com/manage/webhooks), then set that page's webhook URL to `https://www.kella.online/api/webhooks/kofi`. Keep the token in the backend environment only. Google sign-in must also be configured for automatic approval.

Ko-fi sends a form-encoded `data` field containing payment JSON. The backend verifies the token and records each qualifying payment once by both message ID and transaction ID. Only a `Subscription` event with `is_subscription_payment: true`, the exact Forest Guardian tier, USD currency, and an amount of at least `$5.00` qualifies. The Ko-fi payer email must exactly match the verified Google account email after trimming and case normalization. If payment arrives before signup, the record is applied when that Google account signs up.

Each qualifying payment covers one calendar month from its Ko-fi payment timestamp. A renewal sets the paid-through date from that renewal's timestamp; replayed deliveries do not extend access. Backend authentication checks this date on every request, including existing sessions. Once verified, the Ko-fi payment email remains bound to that account and renewals follow that binding. Ko-fi currently sends [payment webhooks only](https://help.ko-fi.com/hc/en-us/articles/360004162298-Does-Ko-fi-have-an-API-or-webhook), so access expires by the paid-through date rather than by a cancellation event. A late renewal restores access when its payment arrives.

Signup opens the payment page with Ko-fi's official embedded checkout. In Ko-fi Payment Settings, enable **Default to memberships** so the Forest Guardian tier appears first. Kella permits the Ko-fi frame only on this page. The page checks `/api/auth/kofi/status` using a limited payment identity cookie and enters the base when access is confirmed; that cookie cannot access member APIs.

All username/password and Google accounts require payment, including accounts approved before this flow was added. New Discord/member-link accounts require it too. Existing Discord owner/admin access is preserved. Manual approval never waives required payment. Google payments matching the verified email can approve automatically. Other users submit their payer email and optional receipt reference for admin review in **Kingdom Members**; these details alone do not prove ownership. An admin must match an unclaimed, verified webhook payment to the applicant. A membership can be bound to only one account.

A manual termination is never reversed by a payment webhook. Ko-fi says [changing a tier price affects new subscribers only](https://help.ko-fi.com/hc/en-us/articles/4402945994001-Ko-fi-Memberships-and-Membership-Tiers); an old `$2` payment does not meet this site's `$5` access requirement.
